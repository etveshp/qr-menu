# AGENTS.md — Правила роботи в цьому репозиторії

Проект: **Aura Cafe QR-Menu (Supabase + Vercel)** — Next.js 15 (App Router) + Supabase (Auth + Postgres).
Тип: прототип, функціонал доробляється.

**Це окрема копія Firebase-версії.** Все акаунти (GitHub, Google, Supabase, Vercel) — окремі, не пов'язані з особистими.

## Головне правило

**Усі зміни виконуються за планом `PLAN.md`. Жодна робота поза планом не починається без підтвердження користувача.**

## Обов'язковий процес роботи

1. **Перед будь-якими змінами** прочитай `PLAN.md` та визнач, до якого етапу належить задача.
2. Виконуй етапи **по порядку** (Фаза 0 → 1 → 2 → …). Не пропускай фази.
3. Після завершення **кожного етапу обов'язково**:
   - запусти тести: `npm test`
   - перевір типи: `npx tsc --noEmit`
   - запусти lint: `npm run lint`
4. Якщо етап виконано успішно:
   - познач його `[x]` у `PLAN.md`;
   - додай запис у «Журнал змін плану»;
   - онови `CHANGELOG.md` (секція поточної версії або нова `## [x.y.z]`): Added / Changed / Fixed / Security / Removed;
   - у відповіді користувачу наведи звіт: що зроблено, команди, якими підтверджено, і результати (кількість тестів, наявність помилок).
5. Якщо етап не вдалося завершити — познач `[blocked]`, поясни причину і що потрібно для розблокування.
6. Звіт про завершення етапу — **обов'язковий**, без нього етап не вважається виконаним.

## Вимоги до коду

- Новий код — на TypeScript, з дотриманням `strict`.
- **Тести обов'язкові** для нової бізнес-логіки (кошик, переклади, валідації, auth). Тести пишуться поряд із кодом у `__tests__/`.
- Не додавай коментарі без потреби. Код має бути самодокументованим.
- Слідуй існуючим конвенціям проекту (паттерни компонентів, `@/` аліас, палітра в Tailwind-класах).
- Не створюй непотрібні файли; перед створенням перевір, чи можна вписатись у наявну структуру.
- **Ніколи не коміть секрети**: ключі API, паролі, креденшели у файли, що потраплять у репозиторій.

## Безпека (пріоритет №1)

- Не залишай хардкод-паролі або креденшели у вихідному коді.
- Будь-який запис до БД має бути захищений RLS-правилами; клієнтські перевірки авторизації — недостатні.
- Якщо під час роботи знайдено вразливість — зупинись і повідом користувача перед продовженням.

## Команди

| Команда | Призначення |
|---|---|
| `npm run dev` | Dev-сервер |
| `npm test` | Запуск тестів (Vitest, разово) |
| `npm run test:watch` | Тести у watch-режимі |
| `npm run test:coverage` | Тести зі звітом покриття |
| `npm run lint` | ESLint |
| `npx tsc --noEmit` | Перевірка типів |
| `npm run build` | Production build |

## Корисне

- Аліас `@/*` вказує на корінь проекту (налаштовано в `tsconfig.json` та `vitest.config.ts`).
- Тестова інфраструктура: Vitest + Testing Library + jsdom (`vitest.config.ts`, `test/setup.ts`).
- Поточний стан робіт історія — у `PLAN.md` (Журнал змін плану).
- `.env.example` — зразок змінних середовища (Supabase).
- `supabase-schema.sql` — SQL-схема таблиць + RLS.
- `supabase-seed.sql` — початкові дані (категорії, товари, cafeInfo).
